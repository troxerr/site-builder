# bartlettwebsitedesign.online

The full static site for Bartlett Website Design: the homepage (`index.html`: dark design with a before/after slider), the 23 demos under `demos/`, the dental-office landing page under `dental/`, six city pages (`bartlett/`, `memphis/`, `germantown/`, `cordova/`, `arlington/`, `lakeland/`), `thanks/` and `thanks/booking-agent/` pages, a branded `404.html`, and their assets. Cloudflare Workers Builds deploys it to production automatically on every push to `homepage-conversion-pass` (the production branch set in the Worker's build settings); other branches get preview builds, using `wrangler.jsonc` to serve the folder as static assets (`.assetsignore` keeps the README and config private).

- `?preview` on the URL shows the dashed testimonial placeholders that visitors don't see.
- Cloudflare adds its email obfuscation and bot-check scripts when it serves pages, so they aren't in these files.
- `_headers` sets security headers on every response and a one-week cache on `assets/` (images aren't hashed, so a replaced image can take up to a week to refresh for repeat visitors).
- `wrangler.jsonc` uses `"not_found_handling": "404-page"`, so unknown paths get `404.html`. It uses root-relative links because it can be served at any path.
- **Nothing is edited by hand.** `index.html`, `dental/`, `demos/index.html`, the six city pages, `thanks/`, `404.html`, `sitemap.xml` and everything in `assets/css/` and `assets/js/` are generated by `npm run build` (`tools/build.mjs`) from `src/`, and committed because Cloudflare deploys the repo root as is. CI fails if a committed file is out of date.
  - `src/pages/*.mjs`: one template per page type (JS template literals, no framework).
  - `src/data/*.json`: the facts, each written once: `site.json` (contact details, prices, founding-deal spots), `faq.json`, `cities.json`, `demos.json`.
  - `src/partials/`: header, footer, mobile bar and the icon sprite. `src/lib/`: the shared HTML helpers, `<head>` and structured data.
  - `src/css/`: Tailwind 3 config and component styles, compiled **once** for every page into `assets/css/site.<hash>.css`. `src/js/`: small scripts bundled with esbuild into `assets/js/<name>.<hash>.js`. The hash changes only when the content does, so browsers can cache them for a long time.
- Demo pages under `demos/` are self-contained sites and are not generated (see "Adding a demo").
- After a successful form send, the homepage goes to `/thanks/`, so each website lead shows up as a `/thanks/` page view in Cloudflare Web Analytics. Booking-agent leads (the `/dental/` form, or the homepage form with the booking-agent plan) go to `/thanks/booking-agent/` instead, so they count separately. Text-back leads go to `/thanks/` with a "Text-back inquiry" email subject.
- The city pages link back to the homepage's `#showcase`, `#work`, `#booking-agent`, `#pricing`, `#about`, `#faq` and `#contact` sections, so keep those ids.
- Cloudflare Web Analytics (cookieless) is the one `static.cloudflareinsights.com/beacon.min.js` tag before `</body>`, on the homepage, city pages, dental page, demos page and 404.

## Development

Needs Node 22 (`.nvmrc`). Setup once: `npm ci`, then `npx playwright install chromium`.

| Command | What it does |
|---|---|
| `npm run build` | Regenerates every page, the stylesheet, the scripts and the sitemap from `src/` |
| `npm run build:check` | Rebuilds, then fails if any committed file changed (CI runs this) |
| `npm run serve` | Serves the site locally at http://127.0.0.1:8080 with the same headers and 404 page as the host |
| `npm run lint` | Validates the HTML |
| `npm test` | Links, SEO tags, accessibility, forms, headers, deploy contents and the URL contract |
| `npm run test:live` | Checks the deployed site (all contract URLs, headers, console errors) |
| `npm run snapshot -- before` / `after`, then `npm run snapshot:compare` | Pixel-compares every main page at three widths before and after a refactor |
| `node tools/demo-contrast.mjs`, `node tools/demo-labels.mjs` | Fix demo contrast and label-name failures axe finds (the demo test requires zero at 375 and 1280 px) |

Sandbox note: in a sandbox that needs a proxy, set `CHROMIUM_PATH` to a Chromium binary, and `NODE_USE_ENV_PROXY=1` for `npm run test:live`.

`tests/url-contract.json` lists every URL that has been shared (texts, posts, the sitemap). They must keep working. Add to it, and remove from it only on purpose.

## Founding-client deal

The first 3 website clients get $100 off (Starter $250, Business $850). In return, if they're happy, they're asked for a Google review, a short quote and permission to show their site.

- **When a spot is taken:** lower `founding.spotsLeft` in `src/data/site.json`, run `npm run build`, push. Every "N of 3 spots left", price, plan name and FAQ entry follows.
- **At 0:** the deal, the founding prices, the plan labels and the FAQ entry (and its structured data) all disappear on the next build. `tests/founding.test.mjs` checks 3, 1 and 0.

## Adding a demo

Run one command with the finished site in a folder:

```
node tools/new-demo.mjs <slug> <folder> --name "Business Name" --type "Roofing · Bartlett" \
  --what "What the demo shows." --category building --chip "Live demo" --chip "5 pages"
```

It copies the site to `demos/<slug>/`, adds the "Demo site" bar and `noindex` to every page, removes any canonical, adds link-preview tags, makes the card thumbnails (`assets/work/`) and the 1200×630 preview (`assets/og/`), adds the record to `src/data/demos.json` and rebuilds. Then add `/demos/<slug>/` to `tests/url-contract.json`, run `npm test` and commit. A demo must not claim to be the business: no canonical, `og:url` pointing off-site, or structured data with the business's URL. The optional `city` and `home` objects in the record put the demo on a city page or in the homepage's random pool.
